## Cache correction before tagging

The [initial CI](https://github.com/noesiscarloslisboa/qlik-code-intel/actions/runs/37953345442)
and [initial dry run](https://github.com/noesiscarloslisboa/qlik-code-intel/actions/runs/37953367809)
failed on candidate `68682878bb74101065c3646795f6fd3088191e0e`: restored Go build
caches linked an older parser, so the new query nodes were missing and operations
were diagnosed as unsupported. CGO does not track the C sources included from
outside the Go binding package. Uncached test results (`-count=1`) do not clear
these compiled objects.

The corrected candidate adds `go clean -cache` before ordinary CI, release
verification, and native tests. Parser and CLI source remained unchanged by this
correction. Workflow lint and all local checks passed again from a clean cache,
followed by the successful remote CI and dry run above. No failed candidate was
tagged or released.

## Limits

Binaries are unsigned. Older operating systems and Windows ARM64 are untested.
Selected retrieval checks do not establish exhaustive recall, complete Qlik
syntax support, runtime lineage, or reload validity. Cloud import reads a saved
version, excludes unsaved editor changes, and depends on the token account's
permissions. It does not execute/reload apps, evaluate names or mapping tables,
read QVD data, fetch reload logs/lineage, or provide MCP/a GUI. Skill example
checks do not evaluate automatic selection or assistant behavior across products.
